## 2024-10-11 - QML Component Accessibility
**Learning:** In Qt/QML, web ARIA tags don't work. Instead, screen readers rely on the `Accessible` attached properties. Context properties in repeaters (like `modelData` and `index`) do not need to be prefixed with the delegate ID (like `tab.index`) inside the Accessible block, and `pressed()` can just be called directly without relying on an ID prefix.
**Action:** Always use `Accessible.role`, `Accessible.name`, `Accessible.description`, and `Accessible.onPressAction` for custom interactive QML components, being careful with implicit context properties.
## 2024-10-23 - QML Component Accessibility for Tabs and Radio Buttons
**Learning:** In QML Accessibility, tabs (`Accessible.PageTab`) should use `Accessible.selected` to map to the correct state (e.g. `QAccessible::State::Selected`). Conversely, elements with the role `Accessible.RadioButton` must use `Accessible.checkable` and `Accessible.checked` to correctly represent their state.
**Action:** Ensure proper state properties are applied based on the accessibility role in custom interactive QML components (`Accessible.selected` for tabs, `Accessible.checkable` and `Accessible.checked` for radio buttons and checkboxes).
## 2024-10-18 - QML Dialog Accessibility
**Learning:** QML dialog panels should define `Accessible.role: Accessible.Dialog`, as well as `Accessible.name` and `Accessible.description` properties. This provides necessary context to screen readers when the dialog is opened and receives focus, replacing standard web ARIA roles.
**Action:** Always verify that components used as floating dialogs (e.g., generic panels, confirmation boxes) declare `Accessible.Dialog` properties.
## 2024-10-13 - [Missing Accessible role and name for grouped status items in QML GameBar]
**Learning:** Some custom UI groupings like the battery status in GameBar.qml display visual icons alongside text but lack grouping `Accessible` properties. Without `Accessible.role` and `Accessible.name` applied to the wrapper, screen readers skip or incorrectly read the information.
**Action:** When creating custom grouped status indicators (like an icon plus a percentage text) in QML, attach `Accessible.role: Accessible.StaticText` and a dynamically bound `Accessible.name` to the wrapper (e.g., Row or Item) so screen readers read the aggregate status as a single, coherent element.
## 2024-11-20 - [Missing Accessible role and name for grouped status items in QML Header]
**Learning:** Similar to GameBar.qml, the Header.qml component contains visual groupings of text and icons (like the Nexora OS logo, status chips, and clock) that lack accessibility properties on their wrapper elements. This causes screen readers to either skip or improperly announce these header elements.
**Action:** When creating or modifying custom grouped status indicators in QML (e.g., custom chips or custom logo groups), attach `Accessible.role` (e.g., `Accessible.StaticText` or `Accessible.Clock`) and a dynamically bound `Accessible.name` to the wrapper so screen readers read the aggregate content.
