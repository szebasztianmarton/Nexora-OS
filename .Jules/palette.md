## 2024-10-11 - QML Component Accessibility
**Learning:** In Qt/QML, web ARIA tags don't work. Instead, screen readers rely on the `Accessible` attached properties. Context properties in repeaters (like `modelData` and `index`) do not need to be prefixed with the delegate ID (like `tab.index`) inside the Accessible block, and `pressed()` can just be called directly without relying on an ID prefix.
**Action:** Always use `Accessible.role`, `Accessible.name`, `Accessible.description`, and `Accessible.onPressAction` for custom interactive QML components, being careful with implicit context properties.
## 2026-10-24 - Accessible.RadioButton vs Accessible.PageTab properties
**Learning:** In QML Accessibility, components with the role `Accessible.RadioButton` must use `Accessible.checkable` and `Accessible.checked` properties. Conversely, components with the role `Accessible.PageTab` should use `Accessible.selected` instead of `Accessible.checkable` and `Accessible.checked` to correctly align with how screen readers announce Tab states.
**Action:** Ensure proper state properties are used based on the Accessibility role. Use `selected` for tabs/lists and `checked`/`checkable` for checkable items like radio buttons and checkboxes.
