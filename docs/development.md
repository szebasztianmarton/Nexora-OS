# Development Guide

How to build, run and extend the Nexora OS MVP 1 desktop prototype.

## Prerequisites

Reference platform: Ubuntu 24.04 with the distribution's Qt 6.4.2 (GCC 13 and Clang both work). Requirements from `CMakeLists.txt`: CMake ≥ 3.22, a C++20 compiler, Qt ≥ 6.4 with Core, Gui, Qml, Quick, QuickControls2 (and Test when `BUILD_TESTING=ON`).

```sh
sudo apt install cmake ninja-build g++ \
    qt6-base-dev qt6-declarative-dev \
    qml6-module-qtqml qml6-module-qtqml-workerscript qml6-module-qtqml-models \
    qml6-module-qtquick qml6-module-qtquick-controls qml6-module-qtquick-templates \
    qml6-module-qtquick-layouts qml6-module-qtquick-window \
    libgl-dev
```

- `libgl-dev` is needed because Qt6Gui's CMake package looks for OpenGL.
- The `qml6-module-*` packages are runtime QML imports; missing ones show up as `module "..." is not installed` when the window loads (also in `tst_qmlsmoke`).
- For a self-built or installer Qt, pass `-DCMAKE_PREFIX_PATH=/path/to/Qt/6.x/gcc_64`.

## CMake presets

Defined in `CMakePresets.json`. All use the Ninja generator, `BUILD_TESTING=ON`, `CMAKE_EXPORT_COMPILE_COMMANDS=ON` and the binary dir `build/<preset>`.

| Preset | Build type | Notes |
| --- | --- | --- |
| `debug` | Debug | default for the scripts |
| `release` | Release | |
| `ci` | Debug | `NEXORA_WARNINGS_AS_ERRORS=ON` (`-Werror`) |

Each has matching configure, build and test presets; the test presets set `QT_QPA_PLATFORM=offscreen` and print output on failure.

```sh
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
```

Cache options:

| Option | Default | Meaning |
| --- | --- | --- |
| `BUILD_TESTING` | `ON` | Build the test suite (adds Qt Test) |
| `NEXORA_WARNINGS_AS_ERRORS` | `OFF` | Add `-Werror` (GCC/Clang) |
| `NEXORA_BUILD_FAKE_EMULATOR` | `ON` | Build `nexora-fake-emulator` and the dev configs (also built whenever tests are) |
| `NEXORA_WITH_SDL3` | `AUTO` | `AUTO`: use SDL3 if found; `ON`: require it; `OFF`: never |

In-source builds are rejected. For personal presets use `CMakeUserPresets.json` (git-ignored).

## Scripts

| Script | Usage | What it does |
| --- | --- | --- |
| `scripts/build.sh` | `scripts/build.sh [debug\|release\|ci] [--test]` | Checks for `cmake`, `ninja` and a C++ compiler, configures and builds with the preset (default `debug`); `--test` runs `ctest --preset <preset>` afterwards. |
| `scripts/run.sh` | `scripts/run.sh [debug\|release\|ci] [-- app args...]` | Builds the preset if the binary is missing (otherwise runs an incremental build), then executes `build/<preset>/bin/nexora-console-ui` with the given arguments. |

## Running

```sh
scripts/run.sh
scripts/run.sh debug -- --input-backend none --log-file /tmp/nexora.log
build/debug/bin/nexora-console-ui --config-dir config/emulators
QT_QPA_PLATFORM=offscreen scripts/run.sh     # no display
```

Options: `--config-dir <dir>`, `--log-file <file>`, `--input-backend auto|evdev|sdl3|none`, `--fullscreen`, `--allow-root`, `--help`, `--version`.

Useful environment variables:

| Variable | Effect |
| --- | --- |
| `NEXORA_CONFIG_DIR` | Configuration directory (below `--config-dir` in precedence) |
| `NEXORA_ALLOW_ROOT=1` | Same as `--allow-root` |
| `QT_QPA_PLATFORM=offscreen` | Run without a display |
| `QT_LOGGING_RULES="nexora.*.debug=true"` | Enable debug output (state transitions, emulator output, input details); some distributions disable debug messages by default |

### Configuration in the build tree

`<appDir>/../share/nexora/emulators` is the default config directory, so `build/<preset>/bin/nexora-console-ui` reads `build/<preset>/share/nexora/emulators/`. The build places there:

- `example.json` (copied from `config/emulators/example.json`; runs `/bin/true`),
- `fake-ok.json`, `fake-fail.json`, `fake-crash.json`, `fake-long.json`, generated by `nexora_generate_dev_config()` in `tests/fixtures/fake-emulator/CMakeLists.txt` with the absolute path of the built fake emulator.

These generated files are build artefacts; do not commit them.

The install rules cover only `nexora-console-ui` (to `bin/`) and `example.json` (to `share/nexora/emulators/`), matching the default lookup. Installation is not a supported or tested workflow in MVP 1.

### Root policy

The app exits with code 2 if run as root, unless `--allow-root` or `NEXORA_ALLOW_ROOT=1` is given (emulators would inherit root privileges). `scripts/run.sh` prints a note when started as root without either override. Do development as a regular user.

### Controller access (input group)

The evdev backend reads `/dev/input/event*` directly. On most distributions these nodes are owned by group `input`:

```sh
ls -l /dev/input/event*
sudo usermod -aG input "$USER"    # then log out and back in
```

The diagnostics screen (F1) shows the backend, its status (including "permission denied" counts) and connected devices. Only devices advertising `BTN_GAMEPAD` are opened. Note: no real controller has been tested with either backend yet.

## Optional SDL3 backend

SDL3 is not packaged for Ubuntu 24.04. Build it from source into a prefix (the SDL3 3.2.x series; 3.2.30 is the version Nexora was compile/link-verified against):

```sh
git clone --depth 1 --branch release-3.2.30 https://github.com/libsdl-org/SDL.git ~/src/SDL
cmake -S ~/src/SDL -B ~/src/SDL/build -G Ninja \
    -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX="$HOME/.local/sdl3" \
    -DSDL_TESTS=OFF -DSDL_EXAMPLES=OFF \
    -DSDL_UNIX_CONSOLE_BUILD=ON   # gamepad/joystick only; skips the X11/Wayland requirement
cmake --build ~/src/SDL/build
cmake --install ~/src/SDL/build
```

SDL's own Linux build dependencies (e.g. `libudev-dev` for device hotplug) are described in SDL's `docs/README-linux.md`.

Then configure Nexora with SDL3 required:

```sh
cmake --preset debug -DNEXORA_WITH_SDL3=ON -DCMAKE_PREFIX_PATH="$HOME/.local/sdl3"
cmake --build --preset debug
```

The configure step prints `Nexora: gamepad backends: evdev=ON sdl3=ON`. With `NEXORA_WITH_SDL3=ON` and no SDL3 found, configuration fails with a message. When built in, `--input-backend auto` prefers SDL3 and falls back to evdev; `--input-backend sdl3` forces it. Executables in the build tree find `libSDL3.so` through CMake's build RPATH; elsewhere you may need `LD_LIBRARY_PATH="$HOME/.local/sdl3/lib"`.

The SDL3 backend has only been compile/link-verified; it has not been exercised with a real controller.

## Adding an emulator configuration

1. Create `<config-dir>/<name>.json`:

   ```json
   {
     "id": "my-emulator",
     "name": "My Emulator",
     "executable": "/usr/bin/my-emulator",
     "arguments": ["--fullscreen"],
     "enabled": true
   }
   ```

2. `id` must match `^[a-z0-9][a-z0-9_-]{0,63}$` and be unique; `name` must be non-empty; `executable` must be absolute or relative to the JSON file's directory (never resolved via `PATH`); `arguments` is an array of strings passed verbatim (no shell: no quoting, globbing or `$VAR` expansion); `enabled` is optional.
3. Restart the app or use **Reload configuration** on the diagnostics screen (not possible while an emulator runs).
4. Check the diagnostics screen for errors, warnings (e.g. unknown keys) and the entry's availability.

The emulator runs with the inherited environment, with the executable's directory as its working directory, and receives SIGTERM if Nexora dies. Nexora makes no claims about compatibility with any specific real emulator.

## Code layout and conventions

```
CMakeLists.txt, CMakePresets.json, cmake/   build configuration
shared/                 nexora_shared (include/nexora/shared/, src/)
apps/emulator-manager/  nexora_emulator_manager (include/nexora/emulator/, src/)
apps/console-ui/        nexora_ui, QML module, nexora-console-ui; src/input/ = nexora_input
config/emulators/       example configuration (installed)
tests/                  unit/, integration/, fixtures/fake-emulator/
scripts/                build.sh, run.sh
```

Conventions observed in the code:

- C++20, no compiler extensions; warnings from `nexora_warnings` (`-Wall -Wextra -Wpedantic -Wshadow -Wnon-virtual-dtor -Woverloaded-virtual -Wcast-align -Wformat=2`); code must build cleanly with the `ci` preset (`-Werror`). Targets that contain Qt-generated QML code apply warnings per source with `nexora_apply_warnings()`.
- `QT_NO_NARROWING_CONVERSIONS_IN_CONNECT` and `QT_NO_URL_CAST_FROM_STRING` are defined for all Nexora code.
- Namespaces per module: `nexora::shared`, `nexora::emulator`, `nexora::input`, `nexora::ui`. Public headers are included as `nexora/<module>/Header.h`; input headers as `input/Header.h`.
- `#pragma once`; one class per `PascalCase.h/.cpp`; members prefixed `m_`; constants `kName` or `PascalCase` statics; `QStringLiteral` for string literals; 4-space indentation.
- Enums exposed to Qt use `Q_ENUM` / `Q_ENUM_NS`; QML types use `QML_ELEMENT` with `QML_UNCREATABLE` where the C++ side owns the object.
- Never block the GUI thread (only `EmulatorManager::shutdown()` waits, at exit). Never start processes through a shell.
- Log through the `nexora.*` categories (`qCInfo(lcProcess)` etc.), not plain `qDebug()`.
- Errors that the user can fix are reported in the UI (status message, card detail or diagnostics) as well as in the log.
- Every behavioural change comes with a unit or integration test (see [testing.md](testing.md)).
