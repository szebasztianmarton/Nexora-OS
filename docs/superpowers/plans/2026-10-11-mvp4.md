# Nexora OS MVP 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the MVP 2 console UI plus the unbooted MVP 3 Buildroot tree into a reliable, controller-first, local-only gaming OS: versioned user data with backup/restore, a library with systems and user metadata, emulator health/history, hardware info, signed and integrity-checked updates with an A/B slot layout, diagnostics export, a completed UI (systems, details, quick menu, accessibility) and release engineering.

**Architecture:** Keep the existing module split (`nexora_shared`, `nexora_emulator_manager`, `nexora_library`, `nexora_system`, `nexora_input`, `nexora_ui`) and add one library, `nexora_update` (`apps/update/`), plus a small CLI `nexora-update-tool` used by the privileged update helper. QML stays presentation-only; every system operation goes through a C++ controller. Privileged work (power, update install) stays in root-owned shell helpers that accept one fixed-format request line over a FIFO and re-verify everything themselves.

**Tech Stack:** C++20, Qt 6.4+ (Core, Gui, Qml, Quick, QuickControls2, Sql, Test), SQLite (QSQLITE), OpenSSL 3 libcrypto (Ed25519, SHA-256), CMake ≥ 3.22 + Ninja, CTest, Buildroot 2026.02.3, GRUB2 (x86_64-efi), BusyBox init.

**Spec:** the "Nexora OS — MVP 4: Production-Ready Gaming Operating System" brief (copied verbatim to `docs/mvp-4-brief.md` by Task 0). Executors read both.

## Global Constraints

- C++20, Qt ≥ 6.4 (Ubuntu 24.04 ships 6.4.2; the image ships 6.9.1). Code must compile with both g++ and clang++ with `-DNEXORA_WARNINGS_AS_ERRORS=ON`.
- Format all C++ with the repo `.clang-format` (`clang-format-18 -i`). CI runs `clang-format-18 --dry-run --Werror` on every tracked `*.cpp`/`*.h` outside `prototypes/`.
- Never build a shell command string from metadata/user input; `QProcess` with an argument list only.
- QML never gets a generic "run command" or "write file" entry point.
- No telemetry, no network access added anywhere.
- Never delete game files. Removing a game from the library hides the row only.
- Atomic writes (`QSaveFile`) for every file the app owns; corrupt files are moved aside, never silently overwritten.
- Every new persistent format carries a version number.
- Do not claim hardware/boot/rollback behaviour in docs unless it was executed; mark everything else "implemented, not verified on hardware/VM".
- `prototypes/` is not touched.
- Commit after each task on branch `feature/mvp4`, message style of existing history (imperative, sentence case), ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Build and test commands (WSL Ubuntu-24.04)

The repository lives on Windows at `D:\nexora OS\Nexora-OS` = `/mnt/d/nexora OS/Nexora-OS` in WSL. Run everything through WSL:

```bash
wsl -d Ubuntu-24.04 -- bash -lc 'cd "/mnt/d/nexora OS/Nexora-OS" && cmake -S . -B ~/nxbuild/<task> -G Ninja -DCMAKE_BUILD_TYPE=Debug -DNEXORA_WARNINGS_AS_ERRORS=ON && cmake --build ~/nxbuild/<task> -j4'
wsl -d Ubuntu-24.04 -- bash -lc 'cd ~/nxbuild/<task> && QT_QPA_PLATFORM=offscreen ctest --output-on-failure -j4'
wsl -d Ubuntu-24.04 -- bash -lc 'cd ~/nxbuild/<task> && QT_QPA_PLATFORM=offscreen ctest --output-on-failure -R tst_<name>'
```

When working in a git worktree, replace the source path with the worktree's WSL path. Use a build directory unique to the task (`~/nxbuild/<task>`) and `-j4` (several agents share 16 cores / 11 GiB). Installed in WSL: Qt 6.4.2 dev + QML modules, libssl-dev, grub-common (grub-editenv), shellcheck, clang-format-18. Root in WSL: `wsl -d Ubuntu-24.04 -u root -- …`.

New tests are added to `tests/unit/CMakeLists.txt` or `tests/integration/CMakeLists.txt` using the existing helper there (read it first; it sets labels `unit`/`integration`).

**Consumes:** `shared::build::{Version,BuildId,Board}`, `shared::readFileLimited`, `shared::writeFileAtomically` (Task 1).

**Trust model (document in docs/update-system.md):** release maintainers hold one or more Ed25519 private keys offline; public keys (PEM) are installed read-only in the image at `/usr/share/nexora/update-keys/*.pem` (dev: `${PROJECT_BINARY_DIR}/share/nexora/update-keys`, empty by default). A bundle is accepted only if `manifest.json.sig` is a valid Ed25519 signature over the exact bytes of `manifest.json` by any installed key. The manifest pins the image by size + SHA-256. Key rotation = ship the new public key in an update signed by the old key. Revocation = remove the key in an update. No key → updates impossible (fail closed).

**Bundle format (a directory, e.g. on a USB stick):**

```

  manifest.json       ≤ 64 KiB
  manifest.json.sig   raw 64-byte Ed25519 signature
  rootfs.ext4         the root filesystem image for one slot
```
